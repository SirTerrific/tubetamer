# Localization

The web UI and the Telegram bot share one small translation layer in `i18n/__init__.py`, with one module per language in `i18n/locales/`. Supported languages are English (`en`), French (`fr`) and Norwegian Bokmal (`nb`). For where the locale is set, see [Configuration](configuration.md). For how each front end uses it, see [Web app](web-app.md) and [Telegram bot](telegram-bot.md).

## How lookup works

English source strings are the translation keys. Code calls `t(locale, "Some English text", **kwargs)`:

1. The locale is normalized with `normalize_locale()`.
2. The key is looked up in that locale's `TRANSLATIONS` dict.
3. If the key is missing, the key itself (the English text) is returned, so a missing translation shows English instead of failing.
4. If `kwargs` are given, they are applied with `str.format`, so placeholders such as `{name}` must be kept as is in every translation.

Because of the fallback, `en.py` only holds the few strings whose English wording differs from the key (for example `"Active"` shows as "Activity"), plus `App Name`, which is `TubeTamer`. `fr.py` and `nb.py` carry the full tables.

## Normalization

`normalize_locale()` accepts anything a user or config might type. Case and `_` versus `-` do not matter, and region variants collapse to the base language: `fr-FR` and `fr_CA` become `fr`; `no`, `nn`, `nb-NO` and any `nb…` become `nb`; `en…` becomes `en`. Anything unknown, or empty, becomes the default `en`. `normalize_time_format()` does the same for `locale`, `12h` and `24h` (it also accepts aliases such as `ampm` and `24hr`).

## Helpers in `i18n/__init__.py`

| Helper | Purpose |
|---|---|
| `app_name(locale)` | Localized app name from the `App Name` key |
| `category_label(category, locale, short)` | Educational/Entertainment, or Edu/Fun when `short` is set |
| `day_label(day, locale, short)` | Weekday name from the canonical `mon`..`sun` codes |
| `format_time`, `format_time_compact` | Time display. `locale` mode uses 24-hour time for `fr` and `nb`, and 12-hour AM/PM for `en`. `12h` and `24h` override that |
| `format_month_day(date, locale)` | Short date, using `MONTHS_SHORT` for `fr` and `nb` |
| `html_lang(locale)` | Value for the HTML `lang` attribute |
| `get_locale(config)`, `get_time_format(config)` | Read the normalized value from `config.app` |

## Where the locale comes from

- **Default:** `app.locale` in the configuration (`BRG_LOCALE` in env mode).
- **Web, per browser session:** `POST /api/locale` (in `web/routers/profile.py`, limited to 30 requests per minute) accepts `{"locale": "fr"}`. It rejects values outside `SUPPORTED_LOCALES`, then stores the choice in the session. `current_locale(request)` in `web/helpers.py` returns the session choice first and the configured default otherwise, so each family member can pick a language.
- **Templates:** `web/shared.py` registers `t`, `cat_label`, `day_label`, `fmt_time`, `html_lang` and `app_name` as Jinja globals. They read `locale` and `time_format` from the render context.
- **Telegram:** the bot uses the configured locale and time format (`app.locale`, `app.time_format`).

- **Android TV:** the app does not choose its own language. `GET /api/v1/info` returns the server's configured locale, which the app stores in its session. `appLanguage()` in `android-tv/.../ui/Locale.kt` maps it with the same rules as `normalize_locale` (`no`, `nn` and variants become `nb`) and accepts only `en`, `fr` and `nb`. The menus then match the video titles the server sends. For any other value, the device language applies. See [Android TV client](android-tv.md).

### Language switcher

The header toggle only offers `SWITCHER_LOCALES`, currently `en` and `fr`. Norwegian still works when set through `app.locale` and shows up in the toggle while it is the active language.

### Translated video titles

YouTube serves a translated title when the channel published one. The first time a session switches to a language that has no stored titles (`get_title_langs()`), the route starts a background task, `backfill_titles_for_locale`, so the response is not blocked. Titles go in the `video_titles` table (see [Data layer](data-layer.md)). `localize_titles()` swaps them into video lists for the request's locale.

## Adding a language

`i18n/locales/README.md` is the full checklist. In short:

1. Create `i18n/locales/<code>.py` with a `TRANSLATIONS` dict, and a `MONTHS_SHORT` tuple if month labels differ.
2. In `i18n/__init__.py`, import it and add it to `SUPPORTED_LOCALES`, `_TRANSLATIONS` and, if wanted, `SWITCHER_LOCALES`.
3. Add a prefix branch in `normalize_locale()`, and a branch in `format_month_day()` if the language has its own month labels.
4. Add it to `_uses_24h()` if the language should default to 24-hour time.
5. Update `config.example.yaml`, `docs/configuration.md` and add tests (`tests/test_i18n.py`, `tests/test_bot_localization.py` show the pattern).

Keep keys identical to the English source, keep placeholders and Markdown structure unchanged, and translate the core web and bot flows together before making a language selectable.
